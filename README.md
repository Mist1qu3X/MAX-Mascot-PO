# MAX — ПО для тач-панели

Полный цикл из макетов, собранный на React + Vite: настройка → приветствие →
съёмка → генерация маскота через нейросеть → результат → снова приветствие.
Веб-версия — первый шаг; дальше этот же билд заворачивается в Neutralino.

## Запуск

Нужны Node.js **20.19+** или **22.12+** и npm. После клонирования:

```bash
npm ci
cp .env.example .env.local
```

В `.env.local` задайте `VITE_KIE_API_KEY` — без ключа kie.ai приложение
запустится, но генерация маскота будет недоступна. `VITE_STATS_API_KEY`
необязателен: без него события останутся в локальном журнале и не будут
отправляться в сервис статистики. Не добавляйте личный `.env.local` в Git:
ключи `VITE_*` встраиваются в клиентскую сборку и доступны пользователю
приложения.

Затем в первом терминале запустите панель:

```bash
npm run dev
```

Откройте адрес, который напечатает Vite (обычно `http://localhost:5173`).
Для камеры используйте `localhost` или HTTPS и разрешите доступ к камере.
В ландшафтном окне сцена сама встаёт по центру в пропорции 9:16.

### Без генерации — для правки интерфейса

```bash
npm run dev:mock
```

Тот же дев-сервер с живой перезагрузкой, но кадр никуда не уходит — ни на
kie.ai, ни на проверку, ни на сервер стикеров, кредиты не тратятся. Шкала
едет как обычно, вместо маскота показывается случайный референс из
`avatar/`, а QR ведёт на страницу стикера с этой картинкой. Статистика пишется
только в локальный журнал.
Ключи в `.env.local` для этого режима не нужны.

- `#result` — сразу экран результата с картинкой;
- `?delay=20` — сколько секунд «рисуется» маскот (по умолчанию 8; больше
  60 — увидеть подпись «Осталось совсем немного…»);
- `?fail=gesture` — вместо результата ошибка: `config`, `network`,
  `policy`, `gesture`, `timeout`, `api`;
- `?mascot=Rectangle-7` — всегда эта картинка (по части имени файла).

Страница стикера в этом режиме открывается прямо с дев-сервера:
`http://localhost:5173/sticker/index.html?i=/avatar/Rectangle-7.png`. Если
открыть панель по сетевому адресу, который печатает Vite, а не по localhost,
QR на экране результата можно отсканировать телефоном в том же Wi-Fi.
Камера по сетевому адресу не включится — для этого есть `#result`.

Заглушка подгружается только в этом режиме — в обычную сборку она не
попадает.

Чтобы QR-код открывал страницу стикера по локальной сети, во втором
терминале запустите `npm run sticker`. Телефон должен быть в той же Wi-Fi
сети, что и компьютер. Сервер необязателен для запуска и генерации: если он
недоступен, приложение использует прямую ссылку на картинку kie.ai.

Проверить production-сборку можно командами:

```bash
npm run build       # результат в web/
npm run preview     # локальный просмотр production-сборки
```

Локальную сборку Neutralino запускают командой `npm run neu:run`.

## Структура

```
src/
  assets/               нужные приложению изображения и woff2-шрифты
  components/
    Stage/              «панель»: пропорции 2160 × 3840 и масштаб --u
    ProgressArc/        полукруглый индикатор прогресса
  hooks/
    useCamera.ts        поток с камеры и снимок кадра
    useCountdown.ts     обратный отсчёт до съёмки
    useGeneration.ts    состояние генерации и шкала прогресса
  services/
    kie.ts              генерация маскота через kie.ai
    stats.ts            статистика: локальная очередь + отправка
  screens/
    Setup/              первый запуск: ориентация и язык
    Welcome/            приветствие (WelcomeScreen + WelcomeLandscape)
    Camera/             съёмка (CameraScreen → CameraPortrait / CameraLandscape)
    Loading/            панель генерации поверх размытой съёмки
    Result/             готовый маскот и QR (ResultScreen + ResultLandscape)
  styles/
    tokens.css          масштаб, цвета, градиенты, сетка, типографика
    fonts.css           подключение VK Sans Display
    reset.css           ресет + режим киоска
```

`src/assets/` и `public/` содержат все визуальные файлы, нужные приложению;
они включены в репозиторий. Локальные папки `assets/` и `en-assets/` —
экспорты макетов и скриншоты для справки, а не файлы приложения. Исходники
не импортируют их, сборка и запуск от них не зависят; эти большие папки
намеренно исключены из Git. В `assets/` есть варианты и копии макетов,
QR-эскизы и отдельный скриншот; `en-assets/` содержит английские макеты
экранов приветствия, камеры и результата. Их можно переименовать или убрать
локально без влияния на приложение.

Экраны переключаются в `App.tsx`. Чтобы открыть нужный сразу (удобно на
панели при отладке) — `#camera`, `#loading` или `#result` в адресе.
`?format=portrait` / `?format=landscape` разово задаёт ориентацию, не трогая
сохранённый выбор — так удобно сверять обе вёрстки подряд.

## Сборка приложения (Neutralino)

    npm run neu:build     # web/ через Vite, затем бинарники в dist/

Бинарники получаются под macOS (arm64, x64, universal), Linux (x64, arm64,
armhf) и Windows x64. Ресурсы — 6.9 МБ, весь пакет около 24 МБ.

Два каталога разведены намеренно: **Vite собирает в `web/`, Neutralino — в
`dist/`**. Пока оба писали в `dist`, сборка приложения упаковывала предыдущую
свою сборку в собственные ресурсы и разрасталась с каждым разом.

### tokenSecurity: none — почему

В конфиге стоит `"tokenSecurity": "none"`, хотя по умолчанию `one-time`.
С `one-time` нативные вызовы **висят молча**: ни ошибки, ни записи в
`neutralinojs.log` — обещание просто никогда не разрешается. Проверено и под
`neu run`, и на релизной сборке, поведение одинаковое.

Плата за `none`: любой процесс на этой машине может дёрнуть нативный API
приложения. Сервер слушает только localhost на случайном порту, панель
выделенная — здесь это приемлемо. На машине общего пользования так делать
не стоит.

### Готовность нативной части

`src/services/desktop.ts` держит одно обещание готовности на всё приложение.
Ждать событие `ready` нельзя: подписка на него сама по себе нативный вызов и
до `init()` не работает — слушатель не регистрируется, событие не приходит.
Поэтому готовность проверяется пробным `readFile` до первого внятного ответа.

Без этого терялось первое событие статистики: `app/launch` уходит на первом
же кадре, попадал в окно до готовности канала и пропадал без следа.

## Языки

`src/i18n.tsx` — весь текст экранов на русском и английском. Строки лежат
массивами, а не одной строкой с переносами: в макете каждая строка это
отдельный `<span>`, переносы расставлены вручную. У горизонтали своя
подводка — там и переносы другие, и обращение на «вы» вместо «ты».

Язык хранится в настройках рядом с форматом и выбирается на экране
настройки. Кнопки смены языка на приветствии больше нет — панель работает
на том языке, который выбрал оператор. На странице стикера кнопки тоже нет:
язык задаёт `?lang=` в адресе, а без него — язык телефона посетителя.

`?lang=en` в адресе задаёт язык разово, не трогая сохранённый — как и
`?format=`.

Английские строки находятся в `src/i18n.tsx` и сверены с локальными
английскими макетами из `en-assets/`. Макеты в Git не входят и для показа
английского интерфейса не требуются. Тексты и переносы интерфейса меняются
в `src/i18n.tsx`.

## Режим киоска

Жесты глушатся в двух местах. В `reset.css` — `touch-action: none`
(именно `none`, а не `manipulation`: тот отключает только двойной тап, а
щипок и панорамирование оставляет), запрет выделения и системного меню по
долгому нажатию. В `src/kiosk.ts` — то, чего CSS не умеет: Ctrl+колесо,
зум с клавиатуры, жесты WebKit (`gesturestart` и родня — в системном
webview щипок приходит отдельными событиями), контекстное меню,
перетаскивание и двойной тап.

Окно поднято `alwaysOnTop` и лишено возможности менять размер: под ним не
должно всплывать ничего постороннего. Обратная сторона — RustDesk и
системные окна тоже окажутся под ним, для обслуживания приложение придётся
свернуть или закрыть с клавиатуры.

## Обрезка кадра камеры

Камера на панели широкоугольная и захватывает лишнее: по бокам прохожие,
снизу стойка и руки. `CAMERA_CROP` в `src/hooks/useCamera.ts` оставляет
центральную половину по ширине (срезано по 25% с каждой стороны) и верхнюю
половину по высоте.

Числа заданы **одни на всех**: снимок режет по ним `capture()`, превью —
`cropTransform()`, которая отдаёт готовый `transform` для `<video>` вместе
с зеркалом. Разъехаться они не могут, иначе человек видел бы одно, а
снимался бы другой кадр. Поэтому же зеркало убрано из CSS: два источника
правды здесь опаснее лишней строки в разметке.

Обрезка съедает три четверти площади, поэтому у камеры запрашивается
3840 вместо 1920:

| сенсор | квадрат | после обрезки |
|---|---|---|
| 1280 × 720 | 720 | 360 × 360 |
| 1920 × 1080 | 1080 | 540 × 540 |
| 3840 × 2160 | 2160 | 1080 × 1080 |

`ideal` не требование — камера послабее отдаст что может.

## Настройка панели

При первом запуске открывается экран выбора **ориентации** и **языка**;
выбор сохраняется в `localStorage`, дальше приложение стартует сразу с
приветствия. Макета на этот экран нет — свёрстан в фирменной палитре, но без
привязки к сетке 2160 × 3840: формат ещё не выбран, поэтому размеры считаются
от меньшей стороны окна.

Вернуться к настройке можно двумя способами:

- `#setup` в адресе — в браузере;
- **удержать три секунды левый верхний угол экрана** — на панели, где
  адресной строки нет, это единственный способ. Жест слушается на документе,
  обычное касание в этом углу продолжает работать как раньше
  (`src/hooks/useSetupGesture.ts`).

Язык пока заглушка: выбор сохраняется и уходит в статистику, но переводов
ещё нет — все экраны на русском.

Ориентация меняет размер макета: `src/format.ts` ставит `data-format` на
`<html>`, а `tokens.css` по нему переключает `--design-w` / `--design-h`,
от которых считается `--u`. Вся вёрстка экранов завязана на `--u`, так что
менять ничего больше не нужно — нужны только сами раскладки под формат.

Оба формата свёрстаны по своим макетам. В горизонтали экраны не
перемасштабированы, а переставлены, поэтому у каждого своя раскладка:
`WelcomeLandscape`, `CameraLandscape`, `ResultLandscape` рядом с
вертикальными, а экран генерации один — в нём меняется только геометрия
панели (`data-format` на `.sheet`). Логика (камера, отсчёт, генерация,
статистика) общая, в раскладках только разметка и стили.

Цикл: касание приветствия → съёмка с отсчётом → кадр уходит в обработку,
экран съёмки остаётся под панелью прогресса в размытии → результат с QR →
касание возвращает на приветствие.

## Как размеры связаны с макетом

Исходник — 2160 × 3840 (@2x от артборда 1080 × 1920). В коде все размеры
пишутся прямо в пикселях макета:

```css
font-size: calc(var(--fz-title) * var(--u));   /* --fz-title: 220 */
```

`--u` в `tokens.css` — это один пиксель макета в пикселях панели:

```css
--u: min(100vw / 2160, 100dvh / 3840);
```

На вертикальной панели 9:16 попадание один-в-один. На панели с другой
пропорцией сцена масштабируется целиком и центрируется — вёрстка не поедет.
Если на конкретной панели нужно наоборот тянуть по ширине во всю, а разницу
съедать вертикальными отступами — достаточно оставить `100vw / 2160`.

Опорные величины (в пикселях макета, все вынесены в `tokens.css`):

| Подзаголовок | 112 / 135 | Regular 400 | 62 от низа заголовка |

только справа.

Что в горизонтали отличается, кроме расстановки:

| | Вертикаль | Горизонталь |
| --- | --- | --- |
| Подзаголовок приветствия | 112 / 135, «Сделай… тебя» | 96 / 116, «Сделайте… вас» |
| Приглашение на приветствии | 144 / 158, по центру снизу | 112 / 135, по правому краю |
| Стрелка к камере | есть | нет |
| Текст у QR | 96 / 106, Regular | 96 / 107, Medium |
| Подпись под карточкой | нет | «Создайте стикер через бот…», 96 / 106, Medium |

Тексты в макетах разные не только по размеру: в горизонтали обращение на
«вы», а на экране результата появилась подпись про бот «Стикеры в MAX».
Приводить вертикаль к «вы» я не стал — скажите, если надо.

Логотипа MAX на экранах нет: заголовок встал на его место, верх на 239
(`--y-top`), на всех трёх вертикальных экранах одинаково. Стрелка к камере
поэтому короче исходной картинки — её рамка снята с макета. В горизонтальных
раскладках текст привязан к низу колонки и остался на месте.

Английские заголовки в вертикали переносятся чаще (256 против 220):
«digital / mascot», «Look / at the / camera» — иначе первая строка камеры
наезжала на стрелку. У горизонтали свои строки, сверенные с её макетами:
`welcomeAccentWide` и `cameraLookWide` в `src/i18n.tsx`.

Кегли и начертания подобраны не на глаз: перебором вариантов с попиксельным
сравнением рендера и макета (см. «Сверка» ниже).

Свечение фона — четыре слоя (две «лампы» сверху, подсвет снизу и вертикальная
подложка) в `--grad-sky`. Параметры подобраны численно по макету.

## Шрифт

**VK Sans Display**. В `src/assets/fonts/` лежат woff2 только тех начертаний,
что нужны экрану — Regular и Bold; полный набор исходников остался в `/fonts`.
Понадобится ещё вес — сконвертировать и дописать `@font-face` в `fonts.css`:

```bash
npx -y wawoff2 # см. README пакета, либо:
node -e "const w=require('wawoff2'),f=require('fs');w.compress(f.readFileSync('IN.ttf')).then(b=>f.writeFileSync('OUT.woff2',b))"
```

Важная деталь: в макете включён стилистический набор **ss01** — это фирменные
альтернативные знаки, в частности «а» без шпоры. Без него буква заметно
отличается от макета, поэтому `font-feature-settings: 'ss01' 1` стоит на
`body` в `reset.css`.

## Камера

`useCamera` держит поток, `useCountdown` — отсчёт. Как это связано:

- Отсчёт стартует **только когда пошёл живой кадр**, а не при открытии
  экрана: пока камера прогревается, цифра стоит на 3.
- Превью зеркальное, снимок делается таким же зеркальным — человек получает
  ровно тот кадр, который видел. Переключается константой `MIRRORED`.
- Кадр кадрируется под пропорции окна превью (как `object-fit: cover`),
  так что фото совпадает с картинкой на экране. Отдаётся в `onCapture`
  строкой `data:image/jpeg`.
- Треки останавливаются при размонтировании — иначе на панели останется
  гореть индикатор камеры.
- Отказ в доступе, отсутствие камеры и прочие ошибки показываются текстом
  прямо в окне превью, отсчёт при этом не идёт.

Что важно знать при запуске:

- `getUserMedia` работает только в защищённом контексте — это `localhost`
  или `https`. **По `http://192.168.x.x:5173` камера не включится**, хотя
  дев-сервер и открывается: проверять надо с самой панели по localhost.
- В Neutralino страница отдаётся с `localhost`, так что там всё в порядке.
  Но системе всё равно нужно выдать приложению доступ к камере: на macOS —
  `NSCameraUsageDescription` в Info.plist, на Windows — разрешение WebView2.
- Если на панели несколько камер, `facingMode: user` может выбрать не ту.
  Тогда понадобится выбор устройства через `enumerateDevices` — скажите,
  добавлю.

## Генерация маскота

`src/services/kie.ts`, модель **Nano Banana 2** на kie.ai. Порядок:

1. кадр уходит base64 на `kieai.redpandaai.co/api/file-base64-upload`
   и получает временную ссылку;
2. `api.kie.ai/api/v1/jobs/createTask` с этой ссылкой в `image_input`;
3. опрос `api/v1/jobs/recordInfo` раз в 2.5 с до `state: success`;
4. картинка скачивается к себе в blob — временная ссылка живёт 3 дня,
   а связь может отвалиться в любой момент.

Промпт собран по схеме `avatar/Frame 2147239707.png`: у всех шестнадцати
референсов одинаковая обёртка («3d стилизованное изображение в стилистке 3d
мультфильма, на чёрном фоне…»), меняется только описание человека — его
модель берёт с фотографии. Промпт — константа `MASCOT_PROMPT`.

### Фон бывает белым — чиним сами

Модель обязана рисовать на чёрном, но примерно **каждый третий кадр**
возвращается с белым фоном. Замер на реалистичном исходнике (человек в
помещении): 2 из 3 чёрные, 1 белый. Промптом не лечится — требование стоит
в промпте дважды, первой строкой и последней, и всё равно не держится.

Поэтому `src/services/backdrop.ts` проверяет результат сам:

1. читает яркость четырёх углов картинки — бесплатно и мгновенно;
2. если светлые все четыре, вырезает фон (`recraft/remove-background`) и
   берёт вырезку: прозрачный PNG на чёрной карточке и есть чёрный фон.

Разделение уверенное, проверено на шести файлах: чёрный фон даёт яркость
0–2, белый — 254–255, порог стоит на 60. Вырезка читается как 0 и повторно
не чинится. Одного светлого угла мало — чиним только когда светлые все
четыре, иначе светлая деталь за плечом ушла бы в ремонт.

Плата — 14 с и 1 кредит, и только на подведшем кадре. У починки свой отрезок
шкалы загрузки (`backdrop`), иначе лоудер замирал бы на 98%. Побочная
польза: вырезка лучше как стикер — прозрачный PNG в MAX аккуратнее квадрата
с фоном.

### Шкала загрузки

Сервис не отдаёт настоящий прогресс, только «в очереди / готово». Раньше
шкала считалась по этапам, у каждого свой отрезок процентов. Модель была
честнее, но ломалась заметнее: подвис запрос — и шкала намертво встала на
асимптоте своего этапа.

Теперь она едет по времени и доходит до конца **за минуту** (`FILL_MS`).
Успели раньше — прыгает в 100% и уходит на результат. Не успели — замирает
на 99%, а подпись меняется на «Осталось совсем немного…»: честнее сказать
это словами, чем делать вид, что проценты ещё идут.

### Проверка кадра до показа результата

`src/services/moderation.ts` — второй слой поверх запрета в промпте. Смотрит
на исходный кадр моделью `gemini-2.5-flash` и отвечает `ok` / `reject` /
`unknown`. Запускается из `useGeneration` **параллельно** отрисовке, по
колбэку `onUpload` — то есть на тот же загруженный файл, второй раз фото не
льём. Вердикт `reject` обрывает генерацию, не дожидаясь картинки.

- **Времени не стоит.** Проверка укладывается в 8–12 с, отрисовка — 30 с и
  больше. На чистом кадре посетитель не ждёт ни секунды лишней.
- **Денег почти не стоит.** 0.02 кредита против 12 за генерацию — в 600 раз
  дешевле. Причём в плюс: забракованный кадр больше не сжигает 12 кредитов.
- **`unknown` намеренно пропускает кадр.** Отказать живому человеку из-за
  моргнувшей сети хуже, чем пропустить спорный: на такой случай остаётся
  запрет в промпте.

Модель выбрана замером, а не по старшинству: `gemini-3-pro` **не заметил**
средний палец у лица и один раз отвалился по таймауту, `gemini-2.5-pro`
отвечал верно, но за 23–29 с. Подробности в шапке файла.

### Главное правило промпта: ничего не дорисовывать

Модель послушна до буквальности. Всё, что в промпте названо утвердительно,
она пририсует даже тому, у кого этого на фотографии нет. Дважды обожглись:

- **«Руки держи скрещёнными на груди»** — и человеку, снятому по плечи,
  кисти приставлялись на уровень шеи. Убрано; теперь «не добавляй руки,
  которых нет на фотографии», а если руки в кадре есть — повторить их
  положение. Проверено на трёх исходниках: без рук — рук нет, со скрещёнными
  руками — руки сохраняются, с жестом — жест гасится, руки опускаются.
- **«Сохрани… очки»** — и очки появлялись у тех, кто без них. Заменено на
  явное «очки, усы, бороду, серьги и головные уборы добавляй только тогда,
  когда они есть на фотографии».
- **«Crop по пояс»** тоже вреден: если человек снят по плечи, модель
  отъезжает шире исходного кадра и дорисовывает недостающий торс вместе с
  руками. Заменено на «сохрани кадрирование оригинала».

При правке промпта проверять надо все три случая сразу — исходник без рук,
со скрещёнными руками и с жестом. Ужесточение одного ломает другой.

Что важно знать:

- **Формат результата — `jpg`.** Тот же кадр весит 1.3 МБ против 4.4 МБ у
  png: скачивание на панель падает с ~3.6 до ~1.5 с, а на телефон посетителя
  втрое. Артефактов на чёрном фоне нет, проверено кропом 1:1. Прозрачность
  не нужна — фон чёрный, бот принимает jpg. Сервис принимает ровно `jpg` и
  `png`; `jpeg`, `webp`, `auto` отклоняет. Переключается `VITE_KIE_OUTPUT_FORMAT`.
- **Две задачи на кадр, берём первую.** Отрисовка гуляет от 26 до 200 секунд
  на одном и том же кадре, и это очередь сервиса, а не наш код. Зато можно
  взять минимум из двух независимых попыток: `firstResult()` ждёт ту, что
  пришла первой, проигравшую отменяет своим контроллером. Платим за обе —
  24 кредита на посетителя вместо 12. Выключается `VITE_KIE_ATTEMPTS=1`.
- **На каждом запросе стоит таймаут** (`REQUEST_TIMEOUT_MS`, 30 с). Без него
  зависший `fetch` висел вечно: `HARD_TIMEOUT` проверяется только в цикле
  опроса и загрузку кадра не покрывал. Из-за этого шкала намертво вставала
  на 12% — на асимптоте этапа «загрузка кадра».
- **Время отрисовки от нас не зависит.** Замеры одного и того же кадра в
  один день: 26 с, 29 с, 40 с, 127 с, 129 с, больше 200 с. Это нагрузка на
  сервис, а не формат и не разрешение — контрольный прогон png сразу после
  двух «медленных» jpg тоже не уложился в 200 с. Ускорять тут нечего;
  единственное, что в нашей власти, — загрузка кадра (1.9 с), создание
  задачи (0.6 с) и скачивание результата.
- **Генерация занимает 25–40 секунд** в спокойное время. Замеры nano-banana-2: 2K — 26.0 и
  27.2 с (12 кредитов), 1K — 75.7 и 73.1 с (8 кредитов). То есть **2K втрое
  быстрее 1K**, вопреки ожиданиям, и качество выше — менять разрешение
  смысла нет. `nano-banana-2-lite` / 1K ещё медленнее (150 с). Под нагрузкой
  сервиса время плавает: ранние замеры давали 57–88 с.
- **Реального прогресса сервис не отдаёт** — только «в очереди / готово».
  Шкала считается по этапам: у загрузки, очереди, отрисовки и скачивания
  свой отрезок процентов, внутри отрезка значение асимптотически подходит
  к его концу. Показываемое значение сглажено — оно не прыгает и никогда
  не идёт назад. Кривая **сама калибруется**: панель помнит длительность
  последних двенадцати генераций и целится в медиану (`useGeneration.ts`).
- **Фильтр Google иногда отклоняет кадр** («violated Prohibited Use
  policy») — на одном и том же фото это срабатывает через раз. Одну
  повторную попытку делаем молча, дальше показываем ошибку.
- **Жёсткий таймаут 4 минуты**, после него экран возвращается к приветствию.
- Ошибки (нет сети, отказ фильтра, таймаут, нет ключа) выводятся текстом на
  месте подписи под дугой, через 5 секунд экран сам уходит на приветствие.
  Отдельного экрана ошибки в макетах нет — если нужен, нарисуйте.

## Статистика

`src/services/stats.ts`. Событие сначала ложится в локальную очередь
(`localStorage`) и только потом уходит в сеть — если интернета нет, очередь
копится и разбирается пачкой через `POST /api/events/batch`, когда связь
вернётся (по событию `online` и раз в 30 секунд). Параллельно ведётся
локальный журнал последних 2000 событий; под Neutralino он дублируется в
файл `stats.jsonl` — с панели его забрать проще, чем localStorage.

`zone` = `max_digital_maskot`, `zone_number` = 1, `user_id` — идентификатор
сессии, по нему события одного посетителя группируются.

Что пишется:

| question | answer |
| --- | --- |
| `app` | `launch` |
| `session` | `start`, `restart` |
| `photo` | `captured` |
| `generation` | `start`, `success`, `failed:network`, `failed:policy`, `failed:timeout`, `failed:api`, `failed:config` |
| `result` | `shown` |

У `generation=success` и `generation=failed:*` в `meta` лежит `ms` —
сколько заняла обработка.

### Локальный журнал — CSV

Под Neutralino каждое событие дописывается в `stats.csv` рядом с приложением:
файл забирается с панели флешкой и открывается чем угодно. Экранирование по
RFC 4180 — кавычки удваиваются, поля с запятыми и переносами берутся в
кавычки, так что `meta` с JSON внутри не ломает разметку.

    at,zone,zone_number,question,answer,user_id,meta
    2026-09-07T05:30:35.867Z,max_digital_maskot,1,app,launch,s-mtqsy1ez-zg1giu,"{""model"":""nano-banana-2""}"

Записи выстроены в очередь: без неё события, случившиеся подряд, дописывались
бы наперегонки и строки могли перемешаться. Заголовок пишется один раз и
только если файла ещё нет — иначе он появлялся бы в середине после каждого
перезапуска панели.

В браузере файловой системы нет, там журнал остаётся в localStorage
(`localLog()`), а отправка на сервер работает одинаково везде.

## QR и стикер — без внешнего хостинга

QR рисуется на панели из ссылки на готового маскота
(`src/components/QrCode/QrCode.tsx`, библиотека `qrcode` в бандле —
интернет для отрисовки не нужен). `generateMascot` возвращает две ссылки:
локальный blob для показа на экране и публичный адрес для кода.

Ключевая деталь, из-за которой всё сходится локально: картинка-результат
лежит на `img-relay.kieops.com` и отдаётся **без** `content-disposition:
attachment` — то есть на телефоне она открывается как картинка, и её
сохраняют долгим нажатием. Хранилище, куда мы льём исходные кадры
(`tempfile.redpandaai.co`), наоборот заставляет скачивать файл — там
`attachment` не отключается ни параметрами, ни якорем, это проверено.

Что за это платим: инструкция «как сделать стикер» остаётся на экране
панели, на телефон она не уезжает. Поэтому весь путь подписан прямо на
экране результата: на плашке с кодом «Сканируйте, чтобы скачать стикер в
MAX», ниже — «Удерживайте картинку, чтобы сохранить. Затем загрузите её в
бот „Стикеры в MAX"». Второй строки в исходных PNG нет, она добавлена к
макету: без неё посетитель застревает на сохранении — QR открывает картинку
в браузере, и её надо именно удержать. В горизонтали под неё поджат кегль
подписи (84 вместо 96), иначе третья строка не влезает по высоте.

Ссылка не вечная — kie.ai удаляет файлы через несколько суток, для
мероприятия хватает.

### Почему не бот

Разбирали вариант получше: свой бот и QR на deep link
`https://max.ru/<бот>?start=<токен>` — тогда посетитель сканирует и сразу
попадает в чат MAX, где маскот уже прислан **файлом** (то есть без пережатия,
в отличие от «сохранить в Фото и загрузить заново»). Хостинг для этого не
нужен: MAX Bot API умеет long polling (`GET /updates`), цикл крутился бы
прямо в ПОшке, а картинку боту можно отдать прямой ссылкой на kie.ai.

Отклонено заказчиком. Ограничения, которые всплыли по дороге, если вопрос
вернётся:

- вложить картинку в **чужой** чат по ссылке нельзя — ни в MAX, ни в любом
  другом мессенджере; `https://max.ru/:share?text=` передаёт только текст;
- бота в MAX может завести только верифицированное **юрлицо РФ**, токен
  выдают после модерации бота;
- `botapi.max.ru` не отдаёт CORS-заголовки, из браузера напрямую не позвать —
  в Neutralino запросы пришлось бы гнать через нативный HTTP;
- payload в deep link — до 128 символов, ссылка на картинку туда не влезет,
  нужен короткий токен и таблица соответствия на панели.

## Хосты kie.ai: два разных, с противоположными свойствами

Результат приходит то с одного хоста, то с другого, и ведут они себя
по-разному — это проверено в браузере, не только curl'ом:

| | `tempfile.aiquickdraw.com` | `img-relay.kieops.com` |
|---|---|---|
| CORS (`fetch`, `<img crossorigin>`) | есть (`allow-origin: *`) | **нет** |
| открытие ссылки на телефоне | скачивает файл (`attachment`) | показывает картинку |

Отсюда два следствия.

**`download()` в `kie.ts` не роняет генерацию.** Если `fetch` запрещён
CORS'ом, функция возвращает исходную ссылку вместо blob: картинку в `<img>`
это показать не мешает, а срывать готовый результат из-за отсутствия
локальной копии — глупо.

**QR прямо на картинку — ненадёжен.** На `aiquickdraw` телефон скачает файл
вместо показа, и на айфоне он ляжет в «Файлы», а не в «Фото» — дальше
инструкция «удерживайте картинку» не работает. Поэтому основной вариант —
страница-посредник.

## Страница для стикера — на самой панели

Хостинг не нужен: страницу раздаёт сама панель по локальной сети.
`server/index.mjs` — маленький сервер на Node, запускается `npm run sticker`.

    npm run sticker
    Страница стикера: http://192.168.1.104:8787/

Как это работает по шагам:

1. Панель сгенерировала маскота и получила ссылку у kie.ai.
2. Панель зовёт `POST /shot` с этой ссылкой. Картинку скачивает **Node**, а не
   браузер, — на CORS ему всё равно, поэтому оба хоста kie.ai одинаково годятся.
3. Сервер отвечает адресом вида `http://<ip панели>:8787/?i=/i/<id>.png` — его
   и кодируем в QR.
4. Телефон в той же сети открывает страницу, жмёт «Сохранить».

**Единственное требование: телефон посетителя в одной сети с панелью.** По
мобильному интернету до панели не достучаться — это плата за отказ от хостинга.

Что локальный вариант даёт сверх «просто заменили хостинг»:

- **Ссылки не протухают** через трое суток, как у kie.ai, и не зависят от
  того, какой из двух хостов выдал результат.
- **Страница и картинка на одном origin** — CORS вообще не при чём, кнопка
  «Сохранить» работает всегда.
- Картинка на панели раздаётся с `content-disposition: inline`, так что даже
  прямая ссылка на неё открывается, а не скачивается файлом.

Картинки живут в памяти, последние 24 штуки; перезапуск панели их стирает.
Для сессии на минуту этого с запасом, а чистить ничего не надо.

`sticker/index.html` принимает ссылку на картинку параметром `?i=<url>`,
показывает маскота, даёт кнопку сохранения, кнопку на бот и пошаговую
инструкцию. Кнопка бота ведёт на `https://max.ru/stickers` — это официальный
«Стикеры в MAX», `@stickers`; можно переопределить параметром `?bot=`.

Шрифт страницы — VK Sans Display, как на панели. Файлы лежат в
`sticker/fonts/` (копии `src/assets/fonts/`), сервер отдаёт их по `/fonts/`.
Без них телефон подставил бы системный шрифт. Сервер на хостинге после этого
изменения нужно пересобрать: `Dockerfile` копирует `sticker/` целиком, шрифты
попадут в образ сами.

Сохранение: на айфоне через `navigator.share` — единственный надёжный способ
положить файл в «Фото»; на остальных устройствах обычная загрузка. Если хост
картинки без CORS и `fetch` запрещён, кнопка открывает картинку отдельной
вкладкой — там её сохраняют долгим нажатием. Картинку показываем **без**
`crossOrigin`: с этим атрибутом она на таком хосте вообще не загрузится.

### Вынести сервер на хостинг (Dokploy)

**Для хостинга сервер вынесен в отдельный репозиторий — MAX-Mascot-web**
(`https://github.com/Mist1qu3X/MAX-Mascot-web`): там только `server/`,
`sticker/`, Dockerfile с проверкой живости и инструкция для Dokploy.
Здесь копия остаётся для локального режима (`npm run sticker`). Меняете
сервер или страницу — переносите правку в оба места.

Локальная схема упирается в одно: телефон обязан быть в том же Wi-Fi. Если
поднять `server/index.mjs` на хостинге с доменом, ограничение снимается —
телефон дойдёт и по мобильному интернету. Панель при этом остаётся локальной,
наружу уезжает только раздача страницы и картинок.

Две переменные меняют режим:

- `PUBLIC_URL` — адрес страницы строится от домена, а не от IP панели;
- `SHOT_TOKEN` — **обязателен на хостинге**. Без него `POST /shot` открыт
  всему интернету: любой заставит сервер качать что угодно и забьёт память.
  Сервер об этом предупреждает в логе при старте.

Собирается по `Dockerfile` в корне: зависимостей нет, образ — `node:22-alpine`
плюс две папки, `server/` и `sticker/`. Панель шлёт токен в `VITE_STICKER_TOKEN`,
он должен совпадать с `SHOT_TOKEN`.

Проверка живости — `GET /health`, отдаёт `{"ok":true,"shots":N}`.

### Запасной путь

Если сервер не поднят или панель не видит сети, `stickerLink()` молча
возвращает прямую ссылку на картинку у kie.ai, а подпись на экране результата
сама меняется на «Удерживайте картинку, чтобы сохранить…». Готовый результат
из-за страницы-посредника не срывается. Работает такой путь хуже — см. таблицу
хостов выше.

Про формат. Официальные требования бота (help.max.ru): **jpg, jpeg, png,
от 288 px по стороне, до 10 МБ**. JPG альфу не поддерживает в принципе,
значит прозрачный фон **не обязателен** — маскот уходит в стикер как есть,
на чёрном фоне. Никакой дополнительной обработки, лишних тридцати секунд
и лишнего кредита на посетителя.

Минус чёрного фона один: в чате стикер будет чёрным квадратом поверх
обоев, а не аккуратно вырезанным силуэтом. Если захотите вырезать —
в `src/services/kie.ts` уже лежит `removeBackground()` через
`recraft/remove-background`: 25–37 секунд, 1 кредит, справляется даже с
тёмными волосами и чёрной рубашкой на чёрном фоне (проверено).
Включается одним вызовом.

Просить прозрачность у самой модели бесполезно — она рисует шахматку
вместо альфы, это проверено отдельно.

## Известные ограничения

- QR-код генерируется приложением из текущей ссылки на стикер с помощью
  библиотеки `qrcode`; локальные QR-эскизы из `assets/` не используются.
- Градиент дуги прогресса сверен только на первых 20 % исходного макета.
  Дальше ramp продолжен до `#c500ff`; при необходимости он меняется в
  `ProgressArc`.

## Ключи и безопасность

Ключи задаются в `.env.local` (он не попадает в Git; шаблон — `.env.example`).
Но надо понимать: **Vite подставляет `VITE_*` прямо в собранный бандл**,
поэтому ключ kie.ai оказывается открытым в `web/assets/index-*.js`. Тот,
кто получит сборку приложения, сможет прочитать ключ и использовать его за
ваш счёт.

Для панели в закрытом контуре это терпимо, но если нужна защита — единственный
способ убрать ключ с устройства это прокси: маленький сервер, который держит
ключ у себя и принимает от панели только «вот фото, сделай маскота». Скажите,
если нужно, — это небольшая работа.

Ещё две вещи, которые стоит знать заранее:

- **Фото уезжает на сторонний временный хостинг** (`tempfile.redpandaai.co`)
  и три дня доступно по прямой ссылке всем, кто её знает. Для мероприятия с
  лицами посетителей это стоит либо принять осознанно, либо закрыть тем же
  прокси.
- В базе статистики есть тестовое событие `question=cors_probe` — я проверял
  доступность метода из браузера. Его можно игнорировать или удалить.

## Neutralino

Конфигурация уже находится в `neutralino.config.json`. `npm run neu:run`
собирает интерфейс в `web/` и запускает Neutralino. `npm run neu:build`
создаёт release-сборку; полученные `web/`, `bin/` и `dist/` не хранятся
в Git.

## Мелочи

- Приглашение «Коснитесь экрана» медленно пульсирует — обычная практика для
  экрана ожидания. Если не нужно, убрать `animation` у `.cta`.
- Размытие подложки под панелью генерации — `--backdrop-blur` в
  `App.module.css`.
- Выделение текста, зум и оверскролл отключены — в `reset.css`.
- Весь цикл проверен прогоном в браузере: приветствие → отсчёт 3-2-1 →
  снимок → прогресс → результат → возврат. Ошибок в консоли нет.
- Слой экрана в `App.tsx` обязан быть с высотой (`.layer`): внутри экранов
  всё держится на `height: 100%` и абсолютном позиционировании, и без
  высоты у родителя нижняя часть обрезается по высоте текста.
